Web Security Configuration Auditor

A Python tool that inspects how a website is set up to protect its visitors, then lists every weakness it finds with a plain-English fix.

View the code on GitHub Run it yourself
audit.py: sample scan of a deliberately misconfigured test server
$ python3 audit.py http://127.0.0.1:8099
[!] Only scan systems you own or are authorized to test.
Summary: 1 High, 2 Medium, 6 Low, 1 Info (select a finding for the fix)
[HIGH]CORS reflects arbitrary Origin with credentials allowed

Why it matters: Any website can make requests as a logged-in visitor and read the answers back. Private data could be exposed.

Fix: Compare the Origin against an explicit allowlist. Never echo it back when credentials are enabled.

OWASP A01:2021 Broken Access Control

[MED]Missing header: Content-Security-Policy

Why it matters: Without a policy, the browser has no rules about where scripts may load from, so a cross-site scripting bug does more damage.

Fix: Send a restrictive policy such as default-src 'self', then tighten it per resource type.

OWASP A05:2021 Security Misconfiguration

[MED]Cookie “PHPSESSID” missing HttpOnly flag

Why it matters: JavaScript on the page can read the cookie, so one injected script can steal the session.

Fix: Add the HttpOnly attribute to session cookies.

OWASP A05:2021 Security Misconfiguration

[LOW]Missing header: X-Content-Type-Options

Why it matters: Browsers may guess a file’s type instead of trusting the server, which can turn harmless files into executable ones.

Fix: Send X-Content-Type-Options: nosniff.

[LOW]Missing header: X-Frame-Options

Why it matters: Other sites can embed the page in a hidden frame and trick visitors into clicking (clickjacking).

Fix: Send X-Frame-Options: DENY, or use the CSP frame-ancestors directive.

[LOW]Missing header: Referrer-Policy

Why it matters: Full page addresses, sometimes holding IDs or tokens, can leak to other sites.

Fix: Send Referrer-Policy: strict-origin-when-cross-origin or stricter.

[LOW]Information disclosure: Server: Apache/2.4.29 (Ubuntu)

Why it matters: Exact version numbers let an attacker look up known exploits for that release.

Fix: Remove or genericize the Server header in the web server configuration.

[LOW]Information disclosure: X-Powered-By: PHP/5.6.40

Why it matters: It reveals the language and version behind the site, and this PHP release is long out of support.

Fix: Disable the header (in PHP, set expose_php = Off) and upgrade.

[LOW]Cookie “PHPSESSID” missing SameSite attribute

Why it matters: The cookie is sent on requests started from other sites, which helps cross-site request forgery.

Fix: Set SameSite=Lax or Strict, and use anti-CSRF tokens on state-changing requests.

[INFO]Missing header: Permissions-Policy

Why it matters: Browser features such as camera and location aren’t explicitly restricted.

Fix: Send a Permissions-Policy header that turns off features the site doesn’t use.

Done. 10 findings, sorted from most to least severe.

The same scan of a hardened test server returned a single Low finding.

ls checks/

security-headers/
Whether the site tells browsers to apply protections: content security policy, HSTS, clickjacking and MIME-sniffing defenses, referrer and permissions policies.
cookies/
Whether each cookie carries the Secure, HttpOnly, and SameSite flags.
cors/
Whether the site lets untrusted origins read its responses, especially while logged in.
encryption/
TLS version, certificate validity and expiry, and whether plain HTTP redirects to HTTPS.
info-leaks/
Headers that reveal software names and version numbers.

Every finding is tagged with its OWASP Top 10 (2021) category.

./run.sh

  1. Get the code. Python 3 is the only requirement. There is nothing to install. 
    git clone https://github.com/Simonxy11/Web-Security-Auditor.git
cd Web-Security-Auditor
  2. Scan a site you own or have permission to test. 
    python3 audit.py https://your-site.example
  3. Save the report as Markdown or JSON. 
    python3 audit.py https://your-site.example -o report.md
python3 audit.py https://your-site.example --format json -o report.json

Authorized use only. The tool sends ordinary requests and no attack payloads, but scanning systems you don’t own or have written permission to test can still be illegal. A local copy of OWASP Juice Shop is a safe place to practice.

cat LIMITS.txt

  • It checks configuration, not code. It won’t find SQL injection or other flaws inside an application.
  • It looks at one page. A full assessment would crawl the whole site.
  • It has been tested on local servers only: a misconfigured one, a hardened one, and an HTTPS server with a self-signed certificate.
